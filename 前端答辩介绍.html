一、项目概览

史·迹 是一款以中国历史人物为主线的交互式地图探索应用。用户选择人物后，在地图上沿着时间轴推进人生轨迹，在关键节点做出抉择，配合诗作展示与生平回顾，沉浸式感受历史人物的传奇一生。

  • 三位人物：李白（唐朝）、李清照（宋朝）、苏轼（宋朝）
  • 核心玩法：地图标记 → 时间线推进 → 关键抉择（二选一） → 诗作弹窗 → 回顾一生
  • 前端工程：React 19 + 高德地图 JS API 2.0，单页应用
  • 数据：本地 JSON 文件驱动，每人约 20-30 个关键事件节点

3.2 状态管理

  • 全局状态：currentView（5 个视图）、player（当前选中人物）— 集中在 App.js
  • 局部状态：currentEventIndex、showChoice、completedChoices、choiceResult 等 — 各组件内部管理
  • Ref 同步：使用 useRef 同步 showChoice / choiceResult，解决 useEffect 闭包陷阱
  • Memo 优化：useMemo 计算 sortedEvents（去重 + 排序 + 过滤）、choiceData、eventPaths
  • 无第三方状态库：项目规模适中，React 内置 Hooks 足够应对

五、核心组件详解

5.1 GameScreen — 地图探索（~1200 行，最复杂组件）

  1. 地图初始化：AMapLoader.load() 动态加载高德地图 JS API 2.0，创建 AMap.Map 实例，设置自定义暖色古风主题样式
  2. Marker 管理：每位人物有专属 PNG 图标（normal 32×32 / selected 40×40），当前选中节点高亮放大
  3. 弧形轨迹线：两点之间使用 二次贝塞尔曲线 计算路径（10 个采样点），showDir: true 显示方向箭头，颜色 #8E2323
  4. 时间轴：底部横向时间轴，每个事件对应一个圆点标记。事件按年份排序，同年仅保留一个（优先选包含"岁"字的）。位置按年份中点线性映射
  5. 关键抉择系统：在特定年份触发二选一，第二个选项永远是正确答案。错误选项显示悲剧结局描述，正确选项推进剧情。通过 completedChoices 数组防止重复触发
  6. 诗作弹窗：事件若有 representative_works 字段，在头像旁弹出古风对话框展示诗作（自动格式化：标题加书名号、内容一句一换行）
  7. 回顾一生：调用 computeFullCurvePath() 绘制所有事件间的完整弧线路径，展示总结文案，调用 map.setFitView() 缩放至全部轨迹
  8. 古今地名显示：底部面板展示"古地名 / 今地名"对照
  9. 头像年龄变化：根据事件年份与出生年份计算年龄，匹配青年 / 中年 / 老年三组头像

5.2 SelectScreen — 角色选择

  • CSS 3D 翻转卡片：通过 transform: rotateY(180deg) 实现正反面切换
  • 传记信息：卡片背面展示 12 个传记字段（人物特征配置驱动，字段映射在 constants 中集中管理）
  • 飞入动画：选中角色后，克隆卡片元素，计算从原位置到容器中心的偏移量，使用 CSS transform 过渡（translate + scale），2 秒后切换到 GameScreen

5.3 RightSidebar — 事件详情面板

  • 可折叠 + 可固定：桌面端默认展开并固定，移动端默认折叠；鼠标悬浮展开，移出后折叠；支持手动固定
  • 关系图：使用 纯 SVG 绘制人际关系网络，中心节点为当前人物，周边节点按角度均匀分布在圆周上。连线中间显示关系文本（如"父亲""配偶"），文本沿连线方向自动旋转
  • 颜色映射：根据事件 color 字段（中文名如"蓝色""红色"）映射到 CSS 颜色值，动态设置文字颜色

七、技术亮点

贝塞尔曲线弧形轨迹

不使用高德地图内置的直线连接，手动计算二次贝塞尔曲线（10 个采样点），轨迹线呈优雅的弧形上翘，避免折线段尖角。控制点垂直于两点连线方向，偏移距离为线段长度的 0.3 倍。

const controlPoint = [
  (lng1 + lng2) / 2 + perpX * offset,
  (lat1 + lat2) / 2 + perpY * offset
];
// B(t) = (1-t)²·P₀ + 2(1-t)t·P₁ + t²·P₂

高德地图与 React 生命周期协调

地图实例存储在 useRef 中，不触发渲染。通过 4 个独立 useEffect 分层管理不同职责：

  1. 地图创建（空依赖，仅执行一次）
  2. Marker 初始化 + 静态线段（依赖人物数据变化）
  3. 弧形箭头绘制（依赖 linePath）
  4. Marker 高亮切换 + 视角移动（依赖 currentEventIndex）

使用 setFitView 自动缩放地图至适合所有标记点，回顾一生时缩放至完整轨迹。

事件去重与排序

原始数据每人超 100 条事件，前端做三层处理：

  • JSON 序列化去重：new Set(events.map(JSON.stringify))
  • 按年份排序：sort((a,b) => a.start_year - b.start_year)
  • 同年合并：同年仅保留一条，优先保留包含"岁"字的状态描述

最终每个角色约 20-30 个关键节点展示在地图和时间轴上。

关键抉择引擎

每个角色在人生关键节点有 3-4 个抉择，触发逻辑完整闭环：

  • 切换事件节点时自动匹配年份查找抉择数据
  • 已完成抉择（completedChoices）不再重复触发
  • 正确 → 显示真实历史故事，继续推进；错误 → 显示"if 历史"悲剧结局，可重新选择

SVG 关系图

纯 SVG 实现人物关系网，不依赖任何第三方图表库。周边节点按角度均匀分布在圆周上，连线中点显示关系文本，文本沿连线方向自动旋转避免倒置。

中式设计系统

以 CSS 自定义属性构建完整的设计语言：

--primary-color: #8E2323;  /* 宫墙红 */
--warning-color: #C09553; /* 琉璃金 */
--light-bg: #F7F3E8;      /* 熟宣色 */
--success-color: #3D675B; /* 墨玉绿 */

按钮模拟"印章+描金"效果（金色阴影）；字体选用衬线 / 楷体；背景纹理由宣纸纹理叠加。

年龄感知头像系统

每位人物配有青年、中年、老年三组头像，系统根据事件年份与出生年份差值自动切换：≤30 岁用青年，31-50 岁用中年，≥51 岁用老年。

十、常见答辩问答

Q1：为什么不用路由库而是用 useState 控制视图切换？
项目只有 5 个页面，且无深层次嵌套路由需求，用 useState 做条件渲染更轻量，避免了 react-router 的额外 bundle 体积。如果后续需要支持 URL 参数（如 /character/li-bai）、浏览器前进后退，再引入路由库也不迟。
Q2：高德地图的 API Key 直接写在前端安全吗？
目前确实是硬编码在 GameScreen.js 中的。生产环境应通过环境变量注入（process.env.REACT_APP_AMAP_KEY），配合 API 域名白名单限制使用范围。当前作为演示项目问题不大，但后续改进方向明确。
Q3：事件去重为什么要用 JSON.stringify 而不是按 ID 去重？
原始数据没有唯一 ID 字段，且部分事件内容相同但顺序不同的情况需要彻底去重。JSON 序列化能保证内容完全一致的条目被合并。配合 Set 结构，代码简洁且可靠。后续数据量增大后应给事件添加唯一 id，改用 id 去重更高效。
Q4：useRef 在地图中起到了什么关键作用？
三个关键用途：① 存储 AMap 和 Map 实例，避免地图对象参与 React 渲染引发重渲染；② 同步 showChoice 和 choiceResult 的最新值给 useEffect，解决闭包中拿到过期状态的问题；③ 存储 Marker 和 Polyline 实例引用，用于在组件更新或销毁时正确清理。
Q5：为什么用 useEffect 分 4 个而不是写在一起？
每个 useEffect 管理不同的生命周期阶段和依赖：地图初始化只执行一次；Marker 创建等人物的 JSON 数据变化才重绘；弧线仅随 linePath 变化；高亮切换随 currentEventIndex 变化。分开写职责清晰、避免不必要的副作用执行、也便于后续维护和调试。
Q6：关系图为什么用 SVG 而不是 Canvas 或 ECharts？
节点数量很少（≤10 个），SVG 的 DOM 操作完全够用，而且 SVG 天然支持 CSS 样式覆盖、事件绑定、无障碍访问。Canvas 适合大数据量但开发成本高，ECharts 引入体积大且自定义样式不如 SVG 灵活。对当前场景 SVG 是最优解。
Q7：三年头像的切换逻辑是否支持更多人物？
完全支持。CHARACTERS 数组中每人配置 avatarYoung / avatarMiddle / avatarOld 三个字段，GameScreen 中 getAvatarForEvent() 按年龄区间映射。新增人物只需在 characters.js 中添加头像路径，代码层面无需任何改动。
Q8：关键抉择的"正确"答案为什么写在第二个选项？
这是业务约定。因为所有抉择的正确选项都是符合历史史实的选择（如李白应诏入京、仗剑去国），统一放在 index 1 使得校验逻辑简洁一致：const isCorrect = optionIndex === 1。如果未来需要支持多选或非线性结局，可以改为在数据中加 correctIndex 字段。
Q9：CSS 自定义属性的设计系统是如何搭建的？
在 common.css 的 :root 中定义统一的色板（宫墙红、琉璃金、熟宣色、墨玉绿等），组件 CSS 通过 var(--primary-color) 引用。好处是一处修改全局生效，且语义化命名让新开发人员能快速理解设计意图。

┄┄ 小白向问题 ┄┄

Q11：为什么不直接用百度地图？
高德地图对古诗词、人文景点的 POI 数据更丰富，开发者文档也写得比较清楚，接入成本低。两款地图都能完成基本功能，选高德主要是个人偏好和数据展示效果。
Q12：这个项目做了多久？
前端主体开发约两到三周，包括页面搭建、地图集成、数据整理和交互调试。数据收集（整理三位人物生平、制作抉择剧情）花的时间甚至比写代码还多。
Q13：这些历史资料是自己编的还是从哪来的？
资料来源于公开的史书资料（《旧唐书》《新唐书》《宋史》）、人物年谱和学术论文。每个事件的时间和地点都做了交叉核对，不是随意编写的。
Q14：三个人物的数据量一样多吗？
不一样。苏轼的事件最多（他一生辗转的地方多、经历丰富），李清照相对少一些。地图上展示的节点数量自然也不同。
Q15：选错了会怎样？
选错会显示一段"假如历史"的结局描述（比如李白选择留在家乡，最终默默无闻），然后可以重新选择。只有选对才能继续往下走。这样设计既保留了教育意义，又不会让用户卡死。
Q16：手机能打开这个网站吗？
可以打开，但推荐用电脑浏览器。高德地图在手机上显示比较拥挤，侧边栏、时间轴这些组件虽然做了自适应适配，但大屏体验明显更好。
Q17：怎么保证历史资料没有硬伤？
主要参考了中华书局出版的正式年谱和权威学者的研究成果。比如李白的出生地存有学术争议（碎叶说 vs 蜀中说），我们在数据中也标注了"尚存争议"。学术上有定论的按定论来，有争议的不强行下结论。
Q18：为什么偏偏选李白、李清照和苏轼这三个人？
三个人分别代表唐诗和宋词的最高成就，人生经历都足够跌宕起伏（多次贬谪、颠沛流离），在地图上有丰富的轨迹可展示。而且他们的知名度高，用户不需要额外了解背景就能上手。
Q19：这个项目和"百词斩""全知识"那些 App 有什么区别？
侧重点不同。那些 App 是通用学习工具，覆盖面广。我们的项目聚焦在"沉浸式体验"——用地图+时间线让人直观感受人物一生走过的地方，关键抉择让用户参与历史决策，诗作弹窗营造文化的沉浸感。更像一个交互式纪录片，而不是学习工具。
Q20：以后还能加别的人物吗？比如杜甫、辛弃疾？
可以。架构上人物是配置化的，只需要在 characters.js 里新增一条配置，配好三组头像、地图图标、事件 JSON 和抉择 JSON，不需要修改任何代码逻辑。加一个人物的主要工作量其实是数据整理和作画。
Q21：弹出窗里的诗是谁写的？
诗作原文都是人物本人的作品（李白的《静夜思》、苏轼的《水调歌头》等），直接从《全唐诗》《全宋词》中摘录。程序只负责自动加上书名号、按照诗句分行展示，没有人工改写。
Q22：地图上那些弯弯的线是怎么画的？
用数学公式（二次贝塞尔曲线）算出一条弧线路径。简单说就是在两点之间取一个向上弯曲的控制点，然后把这条弧线均匀切分成 10 个小段逐段画出来，配合箭头表示移动方向。不是鼠标手画的。
Q23：点错了能不能回到上一步？
可以。底部有"上一步"按钮，时间轴上的圆点也可以直接点击跳转到任意节点。唯一限制是在触发"关键抉择"时不能切换节点，必须完成或重选后才能继续。
Q24：为什么头像会有少年、中年、老年的变化？
为了让用户更直观地感受到人物的年龄增长。程序自动计算事件发生时的年龄，30 岁以下用青年画像，30–50 岁用中年，50 岁以上用老年。三个人物各自绘制了三组不同年龄的画像。
Q25：后续有哪些可优化方向？
① API Key 从硬编码改为环境变量注入；② 引入 react-router 支持 URL 路由和 history 导航；③ 用 TypeScript 重写提高类型安全性；④ 用 React.lazy + Suspense 做代码分割，减少首屏加载体积；⑤ 事件数据增加唯一 ID 字段；⑥ 将关键抉择的正确索引改为数据字段配置，提升灵活性。
